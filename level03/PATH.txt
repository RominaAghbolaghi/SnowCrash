PATH Hijacking




دقیقاً درست! ✅ سیستم PATH را از چپ به راست می‌گردد، اول /tmp/myfolder را نگاه می‌کند، و همین که echo را آنجا پیدا کرد، همان را اجرا می‌کند و دیگر دنبالِ بقیه نمی‌گردد. این همان نکته‌ای است که حمله‌ی ما را ممکن می‌کند.

حالا بریم بسازیمش. 🔧

قدم‌به‌قدمِ حل
قدم ۱: یک پوشه‌ی کاری بساز
cd /tmp
mkdir myexploit
cd myexploit

چرا /tmp؟ چون level03 در پوشه‌های دیگر حقِ نوشتن ندارد، ولی در /tmp همه می‌توانند بنویسند. (یادت باشد راهنمای پروژه گفت /tmp گاهی پاک می‌شود — برای همین مدرک را بعداً جای امن نگه می‌داریم.)



قدم ۲: یک echoِ جعلی بساز

ما می‌خواهیم به‌جای چاپِ متن، برنامه getflag را اجرا کند. فایلی به اسمِ echo بساز:


which getflag
/bin/getflag

echo '#!/bin/bash' > echo
echo '/bin/getflag' >> echo
 ls -la echo

یک لحظه صبر — اینجا یک ظرافت هست. ما داریم از دستورِ echoِ واقعیِ shell استفاده می‌کنیم تا محتوا را داخلِ فایلِ echoِ جعلی بنویسیم. این دوتا فرق دارند:

echo که الان تایپ می‌کنی → دستورِ واقعیِ shellِ خودت.
فایلِ echo که ساخته می‌شود → اسکریپتِ جعلیِ ما.


export PATH=/var/tmp/myexploit:$PATH
PATH=/var/tmp/myexploit:$PATH    /home/user/level03/level03 faghat baraye in ejra path ro taghir mide
بخشِ اول فقط «دفترچه‌ی تلفن» را برای همین یک اجرا عوض می‌کند: اول پوشه‌ی ما، بعد بقیه.

بعد سیستم این مراحل را طی می‌کند:

۱. level03 اجرا می‌شود          →  با هویتِ flag03 (چون SUID)
۲. داخلش: system("env echo ...") →  می‌خواهد echo را صدا بزند
۳. env دنبالِ echo می‌گردد        →  می‌رود سراغِ PATH
۴. PATH اول /var/tmp/myexploit    →  echoِ جعلیِ ما را پیدا می‌کند ✋
۵. echoِ ما اجرا می‌شود           →  داخلش نوشته: /bin/getflag
۶. getflag اجرا می‌شود            →  با هویتِ flag03 → توکن! 🎯

کلِ جادو در قدمِ ۴ است: چون پوشه‌ی ما اول در PATH است، echoِ واقعیِ سیستم (/bin/echo) هیچ‌وقت نوبتش نمی‌شود.


چرا هویتِ flag03 تا آخر حفظ می‌شود؟

این نکته‌ی ظریف و مهم است: وقتی یک برنامه‌ی SUID (level03) برنامه‌ی دیگری را صدا می‌زند، آن هویتِ قدرتمند به بچه‌هایش هم ارث می‌رسد. پس echoِ ما، و بعد getflag، همه در زنجیره‌ی flag03 اجرا می‌شوند.

/ = ریشه (racine | root). همه‌چیز از اینجا شروع می‌شود.
/tmp = جای فایل‌های موقت (temporary). همه حقِ نوشتن دارند، ولی گاه‌به‌گاه پاک می‌شود.
/etc = جای فایل‌های تنظیماتِ سیستم (configuration). مثلاً /etc/passwd که لیستِ کاربرهاست. معمولاً فقط root حقِ نوشتن دارد.

نکته: وقتی یک مسیر با / شروع می‌شود (مثلِ /tmp)، به آن absolute path (chemin absolu) می‌گویند — یعنی از ریشه می‌شمارد و همیشه یک جای مشخص است، فرقی نمی‌کند الان کجا باشی.

می‌خواهی ببینی واقعاً وجود دارند؟ بزن:

ls -ld / /tmp /etc
