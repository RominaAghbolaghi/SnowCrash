system file:
1. /usr : برنامه‌ها و ابزارهای سیستم
User System Resources
دایرکتوری /usr شامل بسیاری از برنامه‌ها، کتابخانه‌ها و منابع نرم‌افزاری سیستم است.

مثلاً:
/usr
├── bin
├── sbin
├── lib
├── share
└── local


مهم‌ترین قسمت‌های آن:
مسیر	کاربرد
/usr/bin	برنامه‌ها و دستورهای عمومی
/usr/sbin	ابزارهای مدیریتی سیستم
/usr/lib	کتابخانه‌های نرم‌افزاری
/usr/share	فایل‌های مستقل از معماری، مثل مستندات
/usr/local	نرم‌افزارهای نصب‌شده محلی

مثلاً وقتی دستور زیر را اجرا می‌کنی:
which ls


ممکن است خروجی این باشد:
/usr/bin/ls


یعنی فایل اجرایی دستور ls در این مسیر قرار دارد.

ارتباط با SnowCrash: فایل مشکوک ما در /usr/sbin/john قرار دارد.

2. /bin : دستورات ضروری سیستم
Essential User Commands
این دایرکتوری شامل دستورات پایه‌ای است که برای استفاده و مدیریت اولیه سیستم ضروری هستند.

مثلاً:
/bin
├── ls
├── cat
├── cp
├── mv
├── rm
├── pwd
└── bash


این دستورات چه کاری می‌کنند؟
دستور	کاربرد
ls	نمایش محتویات دایرکتوری
cat	نمایش محتوای فایل
cp	کپی فایل
mv	جابه‌جایی یا تغییر نام
rm	حذف فایل
pwd	نمایش مسیر فعلی
bash	اجرای Shell

نکته فنی: در نسخه‌های جدید Ubuntu، معمولاً /bin یک Symbolic Link به /usr/bin است.

یعنی ممکن است:
/bin -> /usr/bin


باشد.

پس همیشه نباید تصور کنی این دو دایرکتوری دو مجموعه کاملاً جدا هستند.

3. /sbin : ابزارهای مدیریتی سیستم
System Administration Binaries
این دایرکتوری شامل ابزارهای مدیریتی و سیستمی است.

مثلاً:
/sbin
├── fsck
├── reboot
├── shutdown
├── ip
└── mkfs


کاربردها:
دستور	کاربرد
fsck	بررسی و تعمیر فایل‌سیستم
reboot	راه‌اندازی مجدد سیستم
shutdown	خاموش کردن سیستم
ip	مدیریت تنظیمات شبکه
mkfs	ایجاد فایل‌سیستم

تفاوت /bin و /sbin از نظر تاریخی این است که اولی بیشتر برای دستورات عمومی و دومی برای ابزارهای مدیریتی سیستم در نظر گرفته شده بود.

امروزه این تفکیک مطلق نیست و بسیاری از توزیع‌ها از ساختار یکپارچه /usr استفاده می‌کنند.



4. /etc : فایل‌های پیکربندی سیستم
مهم برای Cybersecurity
این دایرکتوری یکی از مهم‌ترین مسیرها برای تحلیل امنیتی Linux است.

/etc شامل فایل‌های Configuration است.

یعنی فایل‌هایی که مشخص می‌کنند سیستم و سرویس‌های آن چگونه کار کنند.

مثلاً:
/etc
├── passwd
├── shadow
├── group
├── hostname
├── hosts
├── ssh
└── sudoers


بیایید چند مورد مهم را بررسی کنیم:
فایل	کاربرد
/etc/passwd	اطلاعات حساب‌های کاربری
/etc/shadow	اطلاعات رمز عبور به شکل Hash و تنظیمات آن
/etc/group	اطلاعات گروه‌های کاربران
/etc/hostname	نام سیستم
/etc/hosts	نگاشت نام Host به IP
/etc/ssh/	تنظیمات SSH
/etc/sudoers	تنظیمات دسترسی sudo

چرا برای Cybersecurity مهم است؟

چون تنظیمات اشتباه در این فایل‌ها ممکن است باعث آسیب‌پذیری شوند.

مثلاً:
- تنظیمات ضعیف SSH
- دسترسی غیرمجاز به اطلاعات کاربران
- تنظیمات اشتباه sudo
- عضویت نامناسب کاربران در گروه‌ها
نکته: در Linux معمولاً رمزهای واقعی کاربران به‌صورت متن ساده در /etc/passwd ذخیره نمی‌شوند. اطلاعات حساس احراز هویت در /etc/shadow نگهداری می‌شود که دسترسی محدودتری دارد.




5. /dev : دستگاه‌ها
Device Files
اینجا یکی از تفاوت‌های جالب Linux با Windows را می‌بینی.

در Linux بسیاری از دستگاه‌ها و منابع سیستمی از طریق فایل‌های مخصوص در /dev قابل دسترسی هستند.

مثلاً:
/dev
├── null
├── zero
├── random
├── urandom
├── sda
└── tty


توضیح موارد مهم:
فایل	کاربرد
/dev/null	دور ریختن خروجی
/dev/zero	تولید جریان بایت‌های صفر
/dev/random	تولید داده تصادفی
/dev/urandom	تولید داده شبه‌تصادفی
/dev/sda	نماینده یک دیسک
/dev/tty	رابط Terminal

یک مثال واقعی از پروژه خودمان
قبلاً این دستور را اجرا کردیم:
find / -user flag00 2>/dev/null


حالا می‌دانی /dev/null چیست؟

ما خروجی خطا را به آن فرستادیم تا نمایش داده نشود.

در واقع:
2>/dev/null


یعنی:

«جریان خطا را به دستگاه null بفرست و دور بریز.»

این یک کاربرد واقعی از دانش Linux در پروژه SnowCrash بود.

6. /var : اطلاعات متغیر سیستم
Variable Data
این دایرکتوری اطلاعاتی را نگهداری می‌کند که هنگام کار سیستم تغییر می‌کنند.

مثلاً:
/var
├── log
├── cache
├── tmp
├── mail
└── lib


مهم‌ترین قسمت‌ها:
مسیر	کاربرد
/var/log	فایل‌های Log سیستم و برنامه‌ها
/var/cache	اطلاعات Cache
/var/tmp	فایل‌های موقت با ماندگاری بیشتر
/var/lib	اطلاعات وضعیت برنامه‌ها و سرویس‌ها
/var/mail	صندوق‌های ایمیل محلی

چرا /var/log برای امنیت مهم است؟
فرض کن کسی تلاش کرده وارد سرور شود.

ممکن است اطلاعات مربوط به این تلاش در Logهای سیستم ثبت شده باشند.

برای مثال:
ls /var/log


ممکن است فایل‌هایی مثل این ببینی:
auth.log
syslog
kern.log


این فایل‌ها می‌توانند برای بررسی اتفاقات امنیتی بسیار مفید باشند.

مثلاً auth.log در سیستم‌های Debian/Ubuntu می‌تواند اطلاعات مربوط به احراز هویت را ثبت کند.

7. /tmp : فایل‌های موقت
Security Sensitive
این دایرکتوری برای نگهداری فایل‌های موقت برنامه‌ها و کاربران است.

مثلاً برنامه‌ای ممکن است هنگام اجرا یک فایل موقت بسازد:
/tmp/temp123


ویژگی‌های مهم:
- معمولاً کاربران می‌توانند داخل آن فایل ایجاد کنند.
- معمولاً فایل‌های موقت ممکن است پس از Restart یا پاک‌سازی سیستم حذف شوند.
- اغلب با Permission خاصی به نام Sticky Bit محافظت می‌شود.
Sticky Bit چیست؟
فرض کن چند کاربر داخل /tmp فایل ساخته‌اند.

اگر هر کاربر اجازه حذف فایل‌های دیگران را داشته باشد، وضعیت خطرناکی ایجاد می‌شود.

Sticky Bit کمک می‌کند کاربران عادی فقط فایل‌های خودشان را حذف کنند، نه فایل‌های کاربران دیگر را.

Permission معمول /tmp:
drwxrwxrwt


حرف t در انتهای Permission نشان‌دهنده Sticky Bit است.

این مفهوم در مراحل بعدی SnowCrash مهم خواهد شد.
